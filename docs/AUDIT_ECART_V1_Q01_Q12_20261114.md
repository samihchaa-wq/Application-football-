**Risque de livraison identifié :** déployer le client Flutter de `main` avant la migration commerciale serait incohérent. Le workflow Cloudflare manuel n'avait pas de garde exigeant le nouveau schéma. **Une PR séparée [#118](https://github.com/samihchaa-wq/Application-football-/pull/118)** propose maintenant un prévol en lecture seule, fail-closed, avant la publication ; tests CI et validation réelle des rejets requis, pas de fusion automatique.

L'intégration GitHub ne dispose pas de commande administrative pour activer ces protections ; procédure de configuration et critères de preuve ajoutés à l'[issue #45](https://github.com/samihchaa-wq/Application-football-/issues/45). Une CI post-push n'est pas équivalente à l'interdiction effective du push direct.

**Portes restantes T1 :** revue migration + sauvegarde/restore, autorisation **explicite** pour l'application Supabase, vérification du schéma ensuite, publication **autorisée distinctement**, tests réels sur Web et mobiles. Aucun de ces actes n'a été effectué au cours de ce contrôle.

## 1. Résumé exécutif

**Verdict : NO-GO V1.** Les douze décisions sont couvertes par un socle de code et/ou des intentions de fonctionnalité, mais **aucune des douze ne possède une preuve complète d'acceptation bout en bout sur Web + serveur + mobiles**. Il faut distinguer **présence du code**, **CI verte au SHA**, **résultat sur appareil** et **résultat serveur réellement observé**.

### Preuves constatées dans le dépôt

- **1 067 fichiers suivis** dans l'arbre Git `main` ; **239 fichiers de tests Dart** sous `test/` et **202 fichiers sous `supabase/tests/`** (*comprenant des fixtures/bootstrap et d'autres fichiers, pas 202 scénarios exécutés*). Ce volume indique un effort de tests automatisés, **pas la recette des douze scénarios complets**.
- **Aucun répertoire `ios/` ni `android/`** à la racine du dépôt `main` ; le projet porte encore `name: as_grinta` et la description héritée « Application officielle ASG. » dans `pubspec.yaml`. Le futur nom de package Dart ne doit pas être modifié aveuglément car les imports en dépendent.
- **Notifications non natives à ce stade :** `lib/core/push/push_client.dart` choisit la version Web via `dart.library.js_interop` et sinon `push_client_stub.dart`, dont `pushSupported()` renvoie `false`. Aucun module APNs/FCM mobile n'est établi dans ce dépôt.
- **GitHub `main` non protégée** à l'instant relevé (GitHub API `branches/main` : `protected=false`). Le simple fait que des workflows existent ne suffit pas à rendre leur réussite obligatoire.
- **Fichier des profils d'Administration** `lib/features/admin/presentation/admin_profiles_section_v2.dart` **identique octet pour octet** au fichier correspondant du dépôt AS Grinta original : même blob SHA `4a1fe4d82b695c1d51c253ae9e41aa5590608e4b`, 652 lignes. C'est un progrès **vérifié de parité de code**, non une garantie de parité des routes, permissions et interactions. `admin_page.dart` n'a pas le même blob SHA que l'original.
- [PR #115](https://github.com/samihchaa-wq/Application-football-/pull/115) maillot portrait et [PR #83](https://github.com/samihchaa-wq/Application-football-/pull/83) vidéo de stade neutre : **fusionnées**. Le rendu réel sur appareils et la vidéo finale ne sont pas certifiés par leur fusion.
- [PR #117](https://github.com/samihchaa-wq/Application-football-/pull/117) apporte **en projet** 1 tenue initiale, ajouts illimités, archivage/restauration, rubrique repliable, migration additive `20261120000000_kits_illimites_par_club.sql`, tests. La branche n'a pas été fusionnée ni la migration appliquée. **Le code actuel de `main` refuse une liste de maillots dont la taille n'est pas égale au nombre de valeurs de `JerseyOption`** dans `lib/core/club/club_kits.dart`, lignes 243–244, 281.
- La documentation de recette `docs/qa_saison_20261113/04_rapport_et_verdict.md` reconnaît explicitement **164 éléments métiers inventoriés mais non vérifiés écran/serveur**, et aucune saison de 30 matchs jouée.
- Dernière observation Supabase : **61 tables `public` listées, RLS activée sur ces 61 tables** ; **2 clubs, 4 matchs, 84 pronostics, 5 publications de composition, 0 session ou événement Live, 0 finalisation sportive, 0 attribution Homme du match, 0 bilan `season_wrapped`, 2 abonnements**. Les comptages sont des instantanés, non des verdicts E2E.
- Les advisors Supabase signalent **164 avertissements** de fonctions `SECURITY DEFINER` exécutables par `authenticated`, **1 avertissement** de protection contre les mots de passe compromis, et **1 information** concernant une table privée RLS sans policy. **Aucun de ces nombres ne prouve à lui seul une fuite** ; prioriser l'examen des privilèges, des contrôles internes et des appels réels A/B.
- Huit Edge Functions commerciales actives, dont `register-account`, `claim-club`, `claim-account`, `manage-user`, `account-email` et `send-push`. L'état « ACTIVE » ne prouve ni remise du message ni succès fonctionnel.
- Dans les fichiers de la campagne `docs/qa_saison_20261113/05_scenario_31_matchs.md`, **4 scénarios M27–M30 sont encore de type coupe**, désormais **V1.1** selon Q01=A : remplacer leurs scénarios par des amicaux/championnats si on conserve un objectif de 30 matchs joués et 1 annulé.

### Lecture des statuts

- **BASE PRÉSENTE / NON VÉRIFIÉ** : code ou schéma identifié, mais chaîne complète non prouvée.
- **PARTIEL / BLOQUÉ** : un composant essentiel est absent de `main` ou une PR requise est en cours.
- **ABSENT SUR MOBILE** : projet natif et canal demandé inexistants au stade contrôlé.
- **VALIDÉ E2E** : **aucun** des douze à cette date. Cela **ne signifie pas** que les douze sont bogués.
